# Goety 主动吟唱、冷却与特殊蓄力边界

0.1.0-dev.18 接入 Conflux 0.1.10 的主动施法入口。Goety 与 Iron 可独立存在；混合编排只进入一次准备和释放流程。

## 配置与普通规则

`goety_nouveau-server.toml`：`[chanting].enabled=true`、`[cooldowns].enabled=true`，两者可以独立关闭。`[chanting].movementRestrictions=true` 独立控制准备期间的移动限制；`[cooldowns].creativeCooldown=false` 默认让创造绕过冷却。关闭吟唱恢复即时释放；关闭冷却不清除原生已有记录，只让此桥接不检查／新增。聚合规则由 Core `[active_casting].chant_mode` 控制，默认最长，可选累加。

普通聚晶调用 `ISpell.castDuration(caster, staff)`，使用已有法杖查找和原生装备／属性修正。`IChargingSpell` 只调用 `castUp`；其常见 72000 tick 默认值是占用物品的上限，不是吟唱时间。

冷却读取 `SEHelper.isOnCooldown`，通过 `SEHelper.addCooldown` 写入原生聚晶记录并同步。不同 Ars 编排与 Goety 原生法杖共享对应聚晶冷却。有效主动发射后每种聚晶只登记一次基础 `spellCooldown(caster)`，不会缩短已有的更长剩余冷却，重复魔符／散射不会重复登记；一次编排中有聚晶冷却未结束会拒绝整次主动施法。生物／假玩家不获得新的玩家冷却记录。

创造模式默认忽略已有聚晶冷却，也不写入新的冷却，资源仍免费。把 `creativeCooldown` 设为 true 可恢复 Goety 原生的创造冷却规则；切回生存后已有冷却仍生效。取消准备和失败发射不产生冷却。发射后即使未命中仍进入冷却；在途与持续触发继续执行、按次支付原有资源。

## 原生显示

在 Goety 原生 `SoulEnergyGui` 内使用相同的 `goety:textures/gui/soul_energy.png` 进度区域与原生位置／显示配置，读取 Core 通知的独立计时。没有灵魂容器但使用 Ars Mana 时也可以显示同样样式的吟唱条。Goety 自己正在施法时优先显示原生状态，不改写玩家正在使用的聚晶、法杖 NBT 或原生施法能力。

混合编排会向开启吟唱的相关提供者发送同一进度：Iron 使用自己的吟唱条，Goety 使用自己的条。两边不读取对方的类或假造对方的状态。

## 吟唱移动（dev.19）

复用 Goety 客户端输入更新入口和原生 `SpellConfig.FullStopCast` 配置。默认准备期间按使用物品的 0.2 移动系数处理，并停止疾跑；若已实际使用物品，不重复施加减速。原生 `fullStopCast=true` 时停止水平输入并禁止跳跃。乘客沿用原生豁免。

移动状态读取现有准备包的独立计时，不依赖进度条是否显示；不伪造使用物品、原生施法能力或魔杖 NBT。准备结束／取消、换维度、死亡和离线使用已有状态清理。纯 Ars 不产生这个状态，独立关闭移动开关可保留吟唱条。此适配和 Goety 原生一样作用于玩家输入，不额外限制怪物或清零击退／外力速度。

## 后续特别审查清单

当前不追求完全重现 Goety 的法杖交互。新增以下法术前必须明确映射：

1. `IChargingSpell / ChargingSpell`：起手用 `castUp`；不能用 `defaultCastDuration`。松手释放、蓄力倍率和中断成本需逐法术设计。
2. `EverChargeSpell`：起手、射击间隔、弹匣／shots、按秒扣费与停止后的冷却分别处理。当前蒸汽魔符仍按现有一次投射逻辑，不引入原生连发控制。
3. `useSpell / stopSpell`：不要仅调用 `SpellResult` 就宣称持续行为完整。需要列出必须保留的粒子、伤害与清理；也可以选择适合 Ars 的固定时长表示。
4. `hasCustomCooldown`：可能由法术内部按目标、召唤、停止或结果登记，不能当成只读的数值查询调用。桥接默认用有效基础 `spellCooldown` 登记聚晶冷却；dev.24 的障碍另按实际结果登记单炸弹 +40 tick／四炸弹 +60 tick，并保留原生冷却缩减。两个入口只延长已有冷却，基础释放回调不会覆盖结果冷却。其他原生按受击数变化的特殊冷却尚未复刻。
5. 法杖物品 NBT 中的 `Cool / Cooldown / Shots / Seconds`：属于原生连续使用，不修改副手法杖来模拟 Ars 连发。
6. 聚晶专用 NBT／specific cooldown：没有对应具体带数据的聚晶实例时，不伪造其绑定身份。当前普通登记聚晶足够；未来回魂等要另外审查。
7. 召唤的数量限制、SummonDown 和维护消耗不是普通冷却，必须保持各自规则。
8. 原生弹射物／云的生成预热继续由实体管理，不能为了吟唱而删除，也不能误当成持续频道长度。

持续会话与实际触发费用已有独立 Core API；新增特殊行为时先确定一次主动施法和后续触发的边界，再决定接入方式。


## 持续吐息（dev.29）

火焰吐息、冰霜吐息和虫群作为效果魔符，只接受自己或 Goety 原生关系判定中的友军作为喷吐者。方块落点目前不接受。施法者、伤害归属、支付者和实际喷吐者保持分离；喷吐者的眼部位置和当前朝向提供几何信息，装备与数值读取原施法者。持续期间重新检查友军关系、实体存活、区块和魔符开关。

原生 `SpellResult` 每 tick 执行，`showWandBreath` 负责原生粒子；匹配法杖、法袍、点燃、冰冻和击杀虫群仍由 Goety 判断。NeoForge 的原生法术伤害属性作用域也保留。使用原生起始与循环音效。Ars 延长时效改变固定寿命；原生 `shotsNumber` 在这三种 ever-charge 法术中是持续 tick 数，并非实体数量。非正数时长不创建会话。

首次触发支付一次，后续每 20 tick 通过 Conflux 的激活事务支付原生报价，实际支付重新经过 Goety 灵魂损耗事件。空资源、无法支付下一次费用、移除或友军关系失效会停止；创造模式保持免费。每次结果的后续 Ars 效果仍按普通效果顺序执行，不把整个后续编排重复到每 tick。

真实玩家喷吐者复用 Goety 输入减速及现有独立配置；持续状态与准备进度分别记录，结束会清除自己的状态，不覆盖其他会话。不会额外减速非玩家生物，也不会修改它们的使用物品状态或魔杖 NBT。网络协议升级到 2，联机双端应更新到同一版本。

Mixin 的几何/伤害改动只在同步原生回调的线程作用域内开启；普通 Goety 调用委托原生接口默认实现。Forge 的旧 Mixin 对接口 super 调用存在字节码改写问题，使用无状态 Java 委托避开，不引入替身施法者。

定向验证覆盖真实原生伤害、显式伤害归属、友军排除、敌方喷吐者拒绝、按秒费用、关系变化、自然结束、移除清理和创造模式。客户端粒子、声音与输入减速的实际观感仍需人工检查。其他持续水流/射线尚未纳入这批。


## 轰击与雷暴（dev.32）

轰击使用与原生雨幕同一有限频道，保留原生发射间隔、每 20 次发射收费与执行者悬浮。雷暴通过原生 useSpell 逐 tick 创建完整落雷陷阱，并使用真正的 useParticle；Ars 准备替代原生起始 20 tick，持续阶段每 20 次结果付费。两者都只接受自己或友军。三叉戟风暴是一次支付的原生区域实体，不作为持续扣费频道；其激活前的 Ars 来源需同步客户端，避免原生持杖检测使其消失。详见 `storm-channel-audit.md`。

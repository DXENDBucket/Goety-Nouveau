# 隧道原生行为核对（dev.42）

固定依赖：NeoForge Goety 3.2.0，Forge Goety 2.5.58.4。使用真正的 `TunnelSpell.blockResult`、`createHole` 与 `HoleBlockEntity.tick`，没有另造开洞或恢复系统。

## 目标、参数与支付

仅接收 Ars 方块命中。实际方块和命中面进入原生回调；作用域内覆盖回调重新进行的八格瞄准，不改变原生魔杖。主块及相邻命中面区块在查询前必须有效且已加载，之后沿用原生 `rightBlock`、配方无关的 `createHole` 排除条件。

原始施法者提供装备、原生 Range/Duration 附魔和费用。Ars 时间修饰每单位增加二十 tick 洞口寿命；非正寿命或溢出值在生成前拒绝。成功创建真实初始洞口才支付一次，后续扩张及到期还原不另收费。创造模式免费。实体目标不会变成开洞执行者。

## 原生扩张与还原

原生区块实体逐 tick 沿命中面的反方向扩张，普通宽度三格，Void 法杖宽度五格。原始旧状态由原生 `SaveBlockEntity` 保存，寿命到期原生回调还原；不会作为挖掘产生掉落。流体、黑名单、方块实体和不可破坏方块仍按原生条件处理。原生允许扩张时对空气产生临时洞口，这一点保留。

只有本附属创建的洞口带持久标记。原生异步产生的子洞口继承标记，并在原生块查询前检查坐标和加载情况。它们不会靠扩张强制加载未加载区块；遇到不能开洞的前进位置，沿用原生终止传播。作用域内的预扫描同样拒绝未加载区块。

附属入口把原生回调中意外缩为 byte 的深度恢复为原生区块实体实际支持的 int。保留其距离及装备计算，不建立人为深度上限。未经过附属入口的原生回调维持原有行为。

## 保存与同步

原生 `HoleBlockEntity.readNetwork` 忽略 ordinal 为零的 DOWN 方向；附属标记的洞口读取后恢复有效的完整方向枚举。其他原生洞口不受此改动影响。

Neo 3.2.0 的 `SaveBlockEntity` registry-aware 重载没有进入 `HoleBlockEntity` 的单参数 network 覆盖，导致常规保存及更新包可能只有旧方块而没有寿命／深度／方向。本附属的 Neo 专用桥在标记洞口上调用原生完整覆盖，确保真正的保存、读取与更新标签包含这些数据；不修改其他原生保存方块。Forge 使用其原生保存路径。

## 针对性验证

双端 `goety_nouveau_tunnel` 各四项通过：真实三格宽／逐层深度／全部原方块到期还原；Void 法杖五格宽、时间修饰、原状态属性和受保护块；真实全元数据保存读取、更新标签、DOWN 方向继续扩张和初始／子洞口加载边界；实体、水、基岩、方块实体、零寿命、资源与创造。

`goety_nouveau_tunnel_edge` 各一项：范围 130 在附属入口形成 int 深度 131；退出作用域后真实原生瞄准／byte 深度仍如原版。这是具体边界验证，不是高强度配置的性能基准。

服务器测试检查了真实原生实体生命周期及实际同步数据，客户端洞口渲染和粒子仍需人工确认。Neo Ars 在进入效果前的方块能力查询不属于本附属加载边界保证。

# 原生钩索接入核对（dev.43）

## 原生执行与角色

两端固定 Goety 3.2.0／2.5.58.4。效果魔符只接受自己或友军玩家作为执行者，实际运行 GrappleSpell.SpellResult，生成实际 VineHook。玩家 SEHelper grappling 状态记录被牵引者；原生钩索完成飞行、碰撞、附着和绳长计算，SoulEnergyEvents 玩家 tick 完成牵引与法杖防摔。没有另写一套绳索物理或替换成普通伤害弹射物。

原施法者承担资源费用，提供法杖、聚晶属性和 Velocity 附魔；实际玩家执行者决定发射位置与朝向。来源记录与原生玩家 owner 分开。使用者自身已有钩索不会让给另一个友军的首次发射误判为免费。

## 费用、收回与会话

成功首次发射扣一次原生费用。再次触发同一施法者的托管钩索，执行原生免费收回，不额外发明持续耗费。创造免费。Core 非独占会话管理有限时长和友军关系；默认使用现有持续效果回退时长，时间增强沿用共有规则。零时长拒绝；每位玩家最多占用一个原生钩索槽位。

不接管普通 Goety 法杖的钩索，也不允许另一个施法者收回当前托管钩索。普通钩索的持物与收回规则保持原样。托管钩索不要求持续持有 Goety 聚晶；关系失效、失去来源／执行者、超出原生 64 格距离、被替换或会话到期即结束。旧钩索清理只会清掉自己的引用，不会误清后来换上的钩索。

原生 GrappleSpell 首次发射把本次 cooldown 设为零，收回则使用原生默认冷却。因此通用主动释放钩子不提前套冷却；托管结束／收回时通过既有原生冷却适配写入原施法者的默认聚晶冷却，仍遵守配置与创造绕过。FakePlayer 用例不证明真实玩家冷却 HUD 显示。

## 客户端与保存边界

使用实际 VineHookRenderer 的完整钩索和维度相关绳索渲染。同步新增施法手标记（普通原生钩索为 -1；托管主手 0／副手 1），修正原生只根据 Goety 聚晶选择手的位置逻辑。客户端不依赖未同步的来源记录。两端原生渲染器的实际调用签名已核对；实际视觉、连接同步时序与音效尚需客户端人工确认。

钩索是瞬时、有限会话实体，不承诺跨重启恢复。原生 VineHook 的 NBT 未完整保存 Projectile owner；本次没有引入一套持久钩索系统。世界卸载／会话结束按共有清理流程处理。

## 验证

命名空间 goety_nouveau_grapple，两端各四项服务器用例通过：

1. 实际原生附着、绳长、玩家 tick 牵引、防摔与零余额免费收回。
2. 原来源法杖、友军 owner 与余额分离、来源已有钩索时新目标仍扣费用，副手标记实际进入同步数据；关系失效仅清目标钩索。
3. 拒绝其他来源接管；原生新钩索替换旧钩索时不被旧会话清除；未标记钩索仍使用原生持物收回。
4. 方块／非玩家／无费用目标拒绝、创造与零时长边界、有限会话到期清理。

只验证本批行为，没有重跑历史魔符全量测试。资源、混入、源代码包和许可声明另做构建产物核对。

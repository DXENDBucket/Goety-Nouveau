# 原生视觉核对（0.1.0-dev.21）

核对实际依赖：Goety 3.2.0（NeoForge 1.21.1）与 2.5.58.4（Forge 1.20.1）。原版聚晶可以显示裂隙；本次修复的是 Ars 接入的生命周期和同步差异，不修改 Goety JAR，也不替换原生渲染器或贴图。

## 虚空裂隙

原版法杖在准备阶段生成裂隙，客户端先跟踪实体，随后收到激活事件。本附属在 Conflux 准备完成、Ars 效果实际触发后生成裂隙，warmup 为零。此前只绕过服务端的法杖使用状态检查；原生 activated 与 closing 是普通字段，事件 100/101 丢失时不能从跟踪数据恢复。

现在只有联动生成的裂隙带有 ACTIVE / CLOSING 同步阶段。生成前发布 ACTIVE，跟踪数据更新时恢复原生 activated、closing 与纹理动画；原生关闭阶段开始后发布 CLOSING，并保存到 NBT。初次跟踪、后来进入附近和重新加载都能恢复阶段。原生音效、吸引、伤害、关闭爆发和到期清理继续交给 Goety。

原生 size 为额外尺寸，默认零并不意味着原生纹理为零：渲染器使用 `(4 + size) × 激活倍率`。但原生维度刷新可将物理包围盒缩成零，Minecraft 的默认距离剔除随后可能拒绝渲染。联动裂隙改用可见图像的包围盒做距离与视锥剔除，保留物理包围盒和 size，不借修图改变吸引或伤害范围。原版聚晶生成的裂隙保持原规则。

## 地拳与其他区域实体

| 实体 | 核对结果 |
| --- | --- |
| EarthFist | 渲染开关与出拳/收拳动画依赖一次性的原生事件 4/5。新观察者开始跟踪联动地拳时，按当前生命周期补发对应事件；只发送给该观察者，未出拳或已删除时不补发，不重播所有玩家的动画。原版聚晶实体不受此处理影响。 |
| IceBouquet / Ghost Fire | 初始显形也依赖事件 4，但其 GroundProjectile 父类会在激活后每 tick 广播，关闭事件也重复发送，已有原生恢复路径；未添加第二套处理。 |
| FirePillar | 视觉由原生服务端粒子广播提供，不依赖裂隙的激活字段或零尺寸纹理。 |
| Cushion | 使用正的基础半径与同步半径数据；默认尺寸不为零。 |
| Hail / Monsoon | 使用正的基础半径及原生粒子广播；没有发现同类一次性激活门槛。 |
| IceChunk | 使用原生实体模型、运动和粒子；没有发现同类事件控制的显形门槛。 |

两版实际 Minecraft 的 ServerEntity 都先发送实体生成与跟踪数据，再调用 StartTracking，因此地拳的恢复事件位于生成数据之后。

## 验证范围

两版均通过五个区域法术 GameTest。新增检查覆盖默认零额外尺寸的裂隙、原生维度刷新后的渲染边界、无激活/关闭事件的跟踪数据恢复、保存读取，以及地拳的出拳/收拳动画恢复。原有伤害、关闭爆发和原版取消规则仍通过。

这些检查使用实际原生实体及元数据/动画回调，但副本位于服务端世界，不能证明真实客户端画面已经验收。客户端贴图、动画观感和多人观察仍需游戏内确认；没有启动游戏或重跑全部法术测试。

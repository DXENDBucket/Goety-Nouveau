# Goety & Nouveau：接入计划与源码核对

## 范围与边界

这是独立附属，modid 为 `goety_nouveau`，依赖 Ars Nouveau、Goety 和 Ars Conflux；不依赖 Iron & Nouveau。`0.1.0-dev.12` 已有五种弹射物替换、十七种效果与四种原生参数增强，不调整整合包流程或擅自添加生存解锁配方。

Core 负责施法上下文、Ars 载体、延续编排、触发计费与物理资源池预留。Goety 附属负责 Goety 法术参数、实体、装备条件、资源访问和特有召唤行为。以后加入其他附属时，通过 Core 共用载体能力，不做 Goety 与 Iron 的互相依赖。

Not Enough Glyphs 等可选载体的接入继续由 Core 管理。Goety 附属不再复制一份附属弹射物兼容代码。

两边保留了 `IFocus`、`ISpell` 和 `SpellStat`。聚晶的 `IFocus.getSpell()` 是较稳定的入口，避免依赖已经有版本差异的内部法术注册表。准备阶段提供了 `FocusSpells` 与 `NativeSpellStats`，不把它们放进不依赖 Goety 的 Core。

## 施法参数与上下文

Goety 原生参数是 potency、duration、range、radius、burning、velocity，不强行套用 Iron 的“卷轴等级”。从 `ISpell.defaultStats()` 取得基准，然后按各法术实际用途映射 Ars 增强；每次执行使用新的 `SpellStat`，避免散射、延迟和持续触发互相改写参数。

Goety 的 `getTarget(caster)` 往往读取原生目标或玩家视线，发射方向也经常直接读取施法者朝向。不能只调用一个 `SpellResult` 就视为已经兼容了 Ars 选点与目标。

后续接入必须分别保留：

- 法术所有者、伤害来源与资源付款者；
- Ars 触发点、命中目标、方向和弹射物速度；
- 原生装备检查所用的法杖上下文；
- 原生法术实体的完整生命周期、命中表现及 Ars 后续效果。

`ISpell` 的 start/use/stop 生命周期和结果方法返回 `void`。真实触发是否成功，需要适配器提供可靠结果，不能在任意调用后无条件提交费用。

## 灵魂能量：用户已确定的默认值

服务端配置 `goety_nouveau-server.toml`：

```toml
[resources]
source = "SOUL_ENERGY"
```

另一个选项是 `ARS_MANA`。这只决定 Goety 魔符触发所用资源，不修改 Goety 原生法术或其他 Ars 魔符。当前已接通灵魂箭的实际扣费：普通弹射物在成功生成时扣费，环绕等重复载体在每次命中时扣费。

原生 `SEHelper` 与 `TotemFinder` 应用于读取 Goety 实际采用的灵魂容器，不能另建一份玩家灵魂能量数据。原生既可能使用玩家储存，也可能使用图腾；资源预留键必须对应同一个物理池，资源种类使用 `goety:soul_energy`，不能因为来自不同魔符就重复预留同一份能量。

已接通的扣费链：`ISpell.soulCost(...)` 计算法术与装备修正，报价应用 `SEHelper.soulDiscount(...)`，实际触发时调用原生灵魂损失事件，再对其最终价格进行预留和扣除。扣除使用 Goety 原生玩家储存/图腾接口，不再调用会重复应用折扣与事件的 `decreaseSouls(...)`。报价不发送有副作用的事件，因此若其他模组在事件中改价，AI/散射预测与实际价格可能不同；实际触发始终按事件后的价格检查余额。

创造模式遵循免费施法规则。持续效果逐次触发检查资源，资源不足停止；散射按预算缩减数量，再由 Ars 生成对称散射。Goety 原生灵魂 API 主要面向玩家；非玩家施法的资源池适配是明确待做项，不能无提示地视为免费或伪造玩家。

## 第一批接入候选

下表中的灵魂箭、冰块、霜冻新星、缠绕、灵魂治疗、幽灵头骨、火球、毒镖均已实现。

| 原生聚晶 ID | 原生法术 | 首先验证的行为 |
| --- | --- | --- |
| `goety:soul_bolt_focus` | Soul Bolt | Ars 载体替换、原生弹射物、完整命中与延续、灵魂计费 |
| `goety:fireball_focus` | Fireball | 普通火球的伤害与点火、装备导致的多发与地狱火变体、实际成功计费 |
| `goety:poison_dart_focus` | Poison Dart | 原生毒镖与命中效果 |
| `goety:iceology_focus` | Ice Chunk | 原生冰块弹射物、速度与落点 |
| `goety:skull_focus` | Haunted Skull | 追踪目标、所有者与寿命 |
| `goety:frost_nova_focus` | Frost Nova | 指定位置的范围效果和目标阵营 |
| `goety:entangling_focus` | Entangling | Ars 实体目标与原生控制效果 |
| `goety:soul_heal_focus` | Soul Heal | 施法者与被治疗者区分，原生友军与治疗表现 |

Soul Bolt 原生会按法杖和装备选取不同弹射物，并使用施法者方向。适配应复用原生实体与命中处理，同时将发射几何替换为 Core 上下文；所有者仍为真正施法者。原生命中之后，Ars 的剩余效果只能执行一次。

普通弹射物保留 Goety 原生的出生偏移、方向加速度、阻力、逐渐转向及碰撞事件；Ars 负责选方向、散射以及加速统计带来的速度倍率。环绕等特殊载体继续使用 Core 的 Ars 轨迹，原生实体通过 `CarrierProxy` 排除自身代理。受管理与 Ars 接管移动是独立标记，不能因为由联动生成就一律取消原生 tick。共享分派和提供者转换入口均先检查服务端世界，避免客户端生成包触发服务器施法者查找。

四种新增效果使用统一的 `GoetyEffectGlyph` 入口与 `EffectFocus` 定义，各自从聚晶读取原生法术和费用。Ars 负责命中位置、目标及增强参数，Goety 专属适配留在本附属。冰块和藤蔓直接创建 Goety 原生实体，后续凝结、追踪、坠落、束缚与消失由原生 tick 完成；霜冻新星复用原生 `SpellExplosion` 和冻结效果，灵魂治疗复用原生数值与治疗粒子方法。治疗以真正施法者为阵营基准，选中的友军不会变成付款者或伤害所有者。无效目标、满血治疗和失败生成不提交费用。冰块不是沿飞行方向发射的替换弹射物，而是命中后在目标上方生成的效果。

原生付款账户只属于 Goety 这次执行。效果入口不把默认灵魂账户写成后续编排的源账户；灵魂箭的命中延续恢复原有的源账户。这样 Iron 等提供者可以继续使用自身配置或显式传入的账户，无需辨认 Goety 的账户类型。共存测试包含真实 Iron 火焰箭命中后接 Goety 缠绕，以及默认/显式源账户不串用的检查。

Wild 法杖的缠绕群体选取以 Ars 命中点为中心，保留原生半径和数量上限；普通缠绕的扩散也能选取附近敌人。实体命中的藤蔓明确绑定目标，避免原生位置扫描转而抓住同位置其他生物。霜冻新星的几何使用真实命中坐标，避免整数方块坐标的偏移。灵魂治疗一次只对同一友军计算一次治疗，目标和范围集合不重复叠加。

后续继续处理更多召唤、持续法术和特殊位移。Goety 的召唤物契约、灵魂维护与消失方式由本附属处理；它们与 Iron、Ars 召唤物的生命周期不能先验地视为相同。

## 分阶段落实

1. **当前基础**：独立双版本项目、共享聚晶读取/参数快照、资源配置、依赖锁定、许可和本地版本控制。
2. **首个可玩切片（已实现）**：Soul Bolt + 灵魂账户适配 + 原生实体命中延续；双版本无 Iron 的真实服务端验证，以及 NeoForge 双附属共存验证。
3. **触发组合**：普通弹射物、触摸、自身、散射、回响轨迹，以及 Core 已支持的可选附属载体；验证资源不足和创造模式。
4. **扩大法术池**：逐一加入上述候选，记录不支持的装备/目标条件；不通过批量盲调 `SpellResult` 宣称全兼容。
5. **生存获得方式**：在可玩链路稳定后单独决定魔符学习、聚晶与原生仪式之间的关系。准备阶段不擅自改变这部分流程。

Ars 整合实机测试使用 `1.21.1-万法归一`，基础环境由用户部署。用户明确指定测试目录后，可以部署匹配的 addon 与 Core 构建；构建脚本本身不自动部署。服务端 GameTest 覆盖原生命中与延续、灵魂容器、散射预算、创造模式、Mana 切换、重复触发与原生损失事件，以及冰块实际坠落伤害、藤蔓束缚、命中坐标、范围友军过滤和治疗费用。客户端外观仍需实机观察。

该实机环境同时安装 Goety & Nouveau、Iron & Nouveau 和一份 Ars Conflux。另有独立的 NeoForge 共存 GameTest，使用真实 Iron 火焰箭与 Goety 灵魂箭检查同一 Ars 形态的载体分派、学习规则及双替换冲突；测试代码不链接 Iron 类，生产依赖也不因此改变。

## 2026-10-11：原生参数与专用增强研究

本节记录研究时的候选；随后 `0.1.0-dev.7` 已落实火球、毒镖、冲击波、风垫与燃烧增强。dev.9 已接入尖牙及延伸、生命吸收、噬魂；磁引仍随掘地法术留待后续。

已用 `javap` 核对固定的 NeoForge 与 Forge Goety JAR：两端 `SpellStat` 都有 potency、duration、range、radius、burning、velocity 六个参数。附魔定义和法术消费者另外核对了上述固定提交的源码。接受某个附魔不等于已完整实现它的行为；接入时仍以发行 JAR 和实际消费者为准。

| 原生参数 | 建议表达 | 边界 |
| --- | --- | --- |
| potency | Ars 强化／减弱 | 使用原生参数单位，各法术收益不同 |
| duration | Ars 延长／缩短时效 | 使用原生单位，不统一宣称每次增加固定秒数 |
| radius | Ars 扩散 | 调整效果半径；不是重新选取远处目标 |
| velocity | Ars 加速／减速 | 保留各弹射物的原生速度、惯性和抛物线，再应用载体速度倍率 |
| burning | “燃烧”增强已实现 | 直接增加原生 burning，含义由支持它的原生法术决定 |
| range | “延伸”增强已在 dev.9 接入尖牙 | 仅用于法术自身的攻击长度、数量等；不能绕开 Ars 形态的选点／射程规则 |

优先考虑“燃烧”。火球、凋灵头颅、幽灵头骨、尖牙等均消费这一参数，适用范围不只一个法术。它和 Ars 点燃效果有区别：后者是命中后另执行一个效果，前者改变 Goety 原生攻击本身。原生 Ignite 每单位增加点燃秒数，尖牙按每单位五秒处理，掘地还会用 burning 判定是否烧炼掉落物；因此不宜把它描述为统一的“附加五秒点燃”。建议初版每个增强增加一个原生参数单位，只对明确支持的 Goety 魔符开放。

range 与 radius 必须保持独立。例如尖牙的 range 同时决定直线尖牙数量及延伸距离，而风垫的 range 主要参与原生选点。转换为 Ars 触发后，风垫的位置已经由 Ars 决定，不能只因原生支持 RANGE 附魔就给它增加一个实际不起作用的“延伸”增强。

### 附魔机制不是都能直接变成通用数值

- **ABSORB**：原生“生命吸收”附魔最高一级，并与 POTENCY 不兼容。后续检查已找到消费者：`ModEvents.DamageEvent` 对具有 Absorbing 标记、主人为玩家的尖牙按伤害事件当前值等量回血。实际固定 JAR 两端的字节码也已确认；Forge 使用 `LivingDamageEvent.getAmount()`，NeoForge 使用 `LivingDamageEvent.Pre.getNewDamage()`。因此原生确有吸血，但当前这一处理专用于尖牙，不是任意法术都能吸血。仅看实体内部方法会漏掉全局事件消费者。
- **SOUL_EATER**：尖牙的回魂是符合原生条件的成功命中，且受 FangGainSouls 配置影响；并非统一的击杀回魂规则。涉及真实灵魂资源收益，后续需要单独核对并设计。
- **MAGNET**：掘地原生代码将掉落物和经验交给玩家，可成为将来的收取增强候选；先核对 Ars 已有收取能力能否表达，避免重复魔符。
- **ROYALTY**：属于另外的附魔机制，未确认有足够通用的法术参数含义，此次不列为优先候选。

具体参数、兼容魔符和装备分支由 Goety 附属管理。Core 只保留通用上下文与增强传递，不加入 Goety 的 burning 等特有字段。增强值应进入本次施法的参数快照，并随延迟实体保留；不能临时给玩家装备或聚晶添加附魔再移除。专用增强的额外费用需要明确定义并纳入触发报价，不能假定原生聚晶费用会自动读取 Ars 增强。

### 下一批法术核对重点

1. **Fireball**：普通实体是 `SmallFireball` 家族，主要是伤害和点火，不能统称为爆炸火球。Nether 法杖会增加侧弹；Malefic Helm 影响出生位置与方向；Unholy 套装改为 HellBolt，命中后留下 Hellfire。普通火球和 HellBolt 不是现有 Soul／Magic Bolt 完全相同的继承链，需要分别保留原生飞行和命中行为。原生一组三发建议算一次聚晶施法费用，Ars 散射的每个独立触发再分别计费。
2. **Poison Dart**：原生 `Arrow` 家族，保留重力、旋转、水中行为、穿透与已命中集合。Wild 法杖改变穿透，Wild 法袍会把普通毒性改为 ACID_VENOM；不能只做一个普通中毒箭外观。每个实际命中继续 Ars 编排，但同一实体不得因碰撞重入重复执行。
3. **Shockwave**：复用原生随机伤害、范围、粒子与声音，中心改为 Ars 触发位置；支持强化和扩散。
4. **Cushion**：创建原生风垫实体，使用 Ars 选点；支持时效和半径。保留实体原生生命周期和作用方式，不再根据施法者视线二次选点。

优先顺序建议为这四种法术加“燃烧”增强。延伸、回魂、收取等在对应法术接入时再落实，不先批量注册没有实际消费者的增强。

`0.1.0-dev.7` 已完成上述优先项。燃烧每个增加一个原生单位，初版支持火球和幽灵头骨；额外费用配置为 `resources.burningCostPerUnit`，默认 5，随实际触发结算。特殊 Ars 载体的法杖火球齐射作为一组共享轨迹的载荷处理，同一次命中会执行各火球载荷与各自 Ars 后续效果，只收费一次；普通载体仍是独立的原生三发飞行。此项是明确新增的轨迹规则，并非原生已有的环绕齐射。

## 0.1.0-dev.9：尖牙与原生参数增强

接入 `biting_focus` 与 `ignite_focus`。尖牙以 Ars 触发点为起点，优先沿来向展开；没有水平来向时使用施法者朝向。潜行保持环形模式，中心改为触发点。保留原生尖牙实体的全生命周期及全局伤害事件。仅在触发点附近寻找可承载地面，不以施法者的高度扫描远处洞穴。

延伸每个增加一个原生 range 单位，直线每列多一枚尖牙并延长 1.25 格；不会扩大 Ars 目标选取，也不会改变原生潜行环形。生命吸收最多一个，与 Ars 强化不兼容，并禁止装备威力加成绕过这一规则。噬魂最高十级；固定 Forge 与 NeoForge 原生消费者对可回魂目标的判断差异仍由原生实体保留，不另写收益事件。

三个新增配置费用均默认 5，与燃烧一样在真实触发报价中计算、按选定资源结算，再应用灵魂折扣与原生扣费事件。没有地面、无资源、无效原始编排或失败生成不扣费。吸血与回魂的所有者依照伤害主人，付款者保持施法者；不能把受击目标设为临时施法者，也不临时改装备附魔。

引燃的生物分支调用完整原生 `touchResult`，方块分支调用原生火焰弹交互，但使用 Ars 的 `BlockHitResult`。不会调用 `rightBlock` 再读取玩家视线。只有实际改变燃烧状态或成功进行方块交互才付费。


## 0.1.0-dev.10：凋零头颅与盛宴

凋零头颅以独立的原生 WitherSkull 实体家族接入，拦截完整原生命中而非仅执行伤害部分；保留凋零、击杀回血、爆炸及装备分支。盛宴在 Ars 选点周围执行原生敌我过滤和尖牙生成，与已有尖牙共用参数与地面放置逻辑。燃烧扩展到两者，生命吸收扩展到盛宴；不会先注册未接入实际消费者的其他增强。详细边界和验证记录见 `simple-spell-audit.md`。
